## 2025-05-15 - Resource Leaks in JSON Providers and Info Disclosure
**Vulnerability:** Several JSON providers (`IjPluginExtensionsScanner`, `IjJsonExtensionProvider`, `CommandProvider`, `ExCommandProvider`, `VimscriptFunctionProvider`) were using `Json.decodeFromStream` and `Json.encodeToStream` without closing the underlying `InputStream` or `OutputStream`. Additionally, `IjPluginExtensionsScanner` was using `e.printStackTrace()`, which could leak sensitive internal information.
**Learning:** `kotlinx.serialization`'s stream-based methods do not automatically close the provided streams. This can lead to resource exhaustion (file descriptor leaks). Using `printStackTrace()` is a common but insecure practice that bypasses the formal logging system and potentially exposes the application's internal structure.
**Prevention:** Always wrap `InputStream` and `OutputStream` in a `.use { ... }` block when performing IO operations in Kotlin to ensure they are properly closed. Use a formal logger (like `vimLogger`) to log exceptions, ensuring that internal details are captured in logs rather than leaked to standard output.
